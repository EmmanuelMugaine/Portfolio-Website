Shape Management System

Java OOP Coursework Project

An interactive console application for managing a collection of shapes — built around an abstract base class, inheritance, and polymorphism, in pure Java with no external dependencies.

What it does

The program lets a user build up a collection of shapes (rectangles, squares, circles, triangles) through a menu-driven console interface, then inspect, translate, scale, or remove them individually or as a group. Each shape knows how to calculate its own area and perimeter, regardless of which type it is.

Technical approach

Shape is an abstract base class that Rectangle, Square, Circle, and Triangle all extend, each implementing its own area and perimeter logic. Calling code can treat any shape polymorphically — it doesn't need to know which concrete type it's holding to ask for its area.

A separate ShapeList class wraps an ArrayList<Shape> and exposes the group-level operations (add, remove, inspect, translate, scale) rather than letting calling code manipulate the raw list directly. The console menu itself is driven by a Scanner loop with input validation, catching InputMismatchException so an unexpected input (like typing a letter where a number's expected) doesn't crash the whole program.

Challenges

The main design decision I had to think through properly was inheritance versus composition. Every shape needs a position, so it was tempting to just have Shape extend a Coordinates class — but a shape has a position, it isn't one, so I gave Shape a Coordinates field instead of extending it. It's a small distinction, but getting inheritance (is-a) and composition (has-a) right matters for keeping a class hierarchy meaning what it says — the alternative would have technically worked but misrepresented the relationship.

The other challenge was purely defensive: console input is unpredictable, and I wanted invalid input to produce a clear re-prompt rather than an unhandled exception ending the program mid-session.

What I'd do differently

  • Add a proper unit test suite (e.g. JUnit) around the area and perimeter calculations for each shape type
  • Consider a simple GUI on top of the existing class structure, since the underlying model doesn't depend on the console interface at all
  • Extract shape validation (e.g. rejecting a negative radius or side length) into a shared method rather than repeating similar checks across shape constructors
